The Problem

RAG answers sound fluent — but hide wrong facts

Retrieval‑Augmented Generation reduces hallucination, yet a single answer often mixes correct and incorrect facts. Today's systems detect that "something is off" but rarely act on it precisely.

Q: “Where and when was Albert Einstein born?”
A: “Einstein was born in 1879 in Munich.”
Birth year ✓ correct  ·  Birth city ✗ wrong (should be Ulm) — only one fact is wrong.
  • Which specific fact is wrong?
  • Can we fix only that fact, not regenerate everything?
  • Did the fix accidentally break a fact that was already right?
Starting Point · FRANQ

FRANQ detects hallucinations — but has three gaps

FRANQ (Faithfulness‑aware Uncertainty Quantification) flags unreliable answers using an AlignScore faithfulness gate and an IF‑ELSE rule. It detects, but it does not repair.

Gap 1

Facts checked in isolation

Attributes of the same entity are verified independently — a suspicious entity doesn't raise doubt on its other facts.

Gap 2

One rigid decision rule

A hardcoded if faithfulness < threshold switch is applied to every question, regardless of context.

Gap 3

No correction

It says “this is probably wrong” — then stops. It never fixes the fact or checks the fix for new damage.

Our Contribution

Three pillars that turn detection into safe correction

1

Dependency‑Aware Graph

Link every fact to its entity, so doubting one attribute triggers re‑checking its siblings. Fixes Gap 1

2

Learned Calibrated Router

Replace the IF‑ELSE with a trained classifier whose confidence is calibrated — 70% sure really means 70%. Fixes Gap 2

3

Targeted Self‑Correction

Repair only the flagged fact via a deeper search — and measure correction‑regret to guarantee no new damage. Fixes Gap 3

Each pillar maps 1:1 to a code module and is isolated in the ablation study.

Pillar 1

Dependency‑Aware Entity–Attribute Graph

Instead of a flat list of facts, we connect every attribute to its entity. Two signals feed the router:

  • Dependency strength — a fact tied to many siblings is riskier to trust alone.
  • Entity suspicion — if any attribute of an entity looks unfaithful, all its attributes become suspect.

This is the “doubt the grandparent → re‑check the grandchildren” effect flat fact‑checking cannot see.

Einstein
├─ birth year
├─ birth city  ⚠ suspicious
├─ occupation
└─ nationality

One shaky fact raises doubt across the whole entity.

Pillar 2

Learned, Calibrated Uncertainty Router

A gradient‑boosted classifier replaces FRANQ's fixed rule. It combines six signals per fact:

  • Faithfulness · Retrieval confidence
  • Semantic entropy · Parametric‑knowledge uncertainty
  • Dependency strength · Entity suspicion (from Pillar 1)

Crucially, its output is calibrated (isotonic on a held‑out split) so the flagging probability is trustworthy.

Calibration error (ECE) — lower is better
0.026
vs 0.602 for FRANQ's fixed rule — about 23× better calibrated.
Pillar 3

Targeted Self‑Correction + a new safety metric

For a flagged fact, we run a focused search of the full source document (not the short snippet the answer came from), and replace only that value — and only if the new value is genuinely better supported.

New metric — Correction‑Regret
Regret = (facts correct before that became wrong after) ÷ (facts correct before)

It answers the question no prior method asks: did fixing one fact quietly break another? 0 = no collateral damage.

Correcting more is not correcting better

Facts corrected76
Correction‑regret0.135

Fixes 3.8× more — but does net harm

Reckless correction "fixes" far more facts, yet its regret is 10× higher and it drops accuracy below the 63.2% baseline. Correction‑regret is the metric that exposes this — and no prior method measures it.
